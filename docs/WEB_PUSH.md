# Web Push alarms

Server-driven Web Push so alarms fire **even when the app/tab is fully closed**
(desktop Chrome/Edge, Android, and home-screen-installed iOS PWAs).

## How it works

1. **Client subscribes** (`src/calendar/notifications/webPush.js`) using the VAPID
   public key baked into `inkling-config.js`. The subscription is POSTed to the
   backend (`/api/push/subscribe`).
2. **Client uploads its alarm schedule** (`pushSchedule.js`) — a flat list of
   `{id, fireAt, title, body, kind}` for the next 7 days, recomputed from the
   calendar on every data change and on app start (`/api/push/schedules`).
3. **Backend scheduler** (`server/lib/push/scheduler.js`) sweeps all users and,
   for each schedule whose `fireAt` has arrived, sends an encrypted push
   (`webPushSend.js`, RFC 8291 + RFC 8292, zero-dep `node:crypto`).
4. **Service worker** (`service-worker.js`) `push` handler shows the
   notification; `notificationclick` focuses/opens the app.

The encryption is verified against the official RFC 8291 §5 test vector:
`node server/lib/push/webPushSend.js --selftest`. Tests:
`node --test server/tests/pushDispatch.test.mjs server/tests/pushRoutes.http.test.mjs`.

## Generate VAPID keys (once)

```
node scripts/gen-vapid.mjs
```

Prints `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` and writes the
public key to `vapid-public.json` (the web build reads it). **Keep the private
key secret — never commit it.**

## Backend env vars (Render dashboard)

| Var | Purpose |
| --- | --- |
| `VAPID_PUBLIC_KEY`  | Same key baked into the client. |
| `VAPID_PRIVATE_KEY` | Secret — signs the push. |
| `VAPID_SUBJECT`     | `mailto:` contact required by push services. |
| `PUSH_RUN_SECRET`   | Shared secret guarding `POST /api/push/run`. |
| `PUSH_SWEEP_MS`     | (optional) internal sweep interval, default 30000. |

The client's public key lives in `inkling-config.js`
(`window.__INKLING_VAPID__`), regenerated by `scripts/write-runtime-config.mjs`
(env `INKLING_VAPID_PUBLIC_KEY`/`VAPID_PUBLIC_KEY`, else `vapid-public.json`).

## ⚠ Free-tier requirement: external pinger

Render's free tier **spins the server down when idle**, so the internal sweep
timer won't be alive at alarm time. To actually fire alarms while the app is
closed, point an external uptime cron at the run endpoint every ~1 minute:

```
POST https://inkling-15yf.onrender.com/api/push/run
Header: X-Push-Secret: <PUSH_RUN_SECRET>
```

Use cron-job.org or UptimeRobot (both free, 1-min). Cold start adds up to ~1 min
of latency to an alarm. A paid always-on instance removes this caveat.

## Deploy notes

- **Frontend** (SW + client) ships from the `inkling` branch → GitHub Pages
  build. Bump `CACHE_VERSION` in `service-worker.js` on each change, and note the
  PWA cache gotcha: an installed app may need a reinstall to pick up a new SW.
- **Backend** is canonical on `inkling` (`server/`). The `render-deploy` branch
  is a stale snapshot — sync the push files (`server/lib/push/*`,
  `server/routes/pushRoutes.js`) and the `index.mjs`/`handleApi.js` hooks plus
  the missing `server/lib/inkling/*` before redeploying.
- **iOS**: web push only works for a PWA added to the Home Screen (iOS 16.4+).
